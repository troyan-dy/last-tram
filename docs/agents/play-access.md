# Как передать игру игроку

**Локальная работа и PR.** В рабочей копии открой `index.html` в браузере. При создании и обновлении PR вставь в его описание и сообщение пользователю ссылку на ZIP текущего head-коммита (`https://github.com/OWNER/REPO/archive/SHA.zip` для репозитория исходной ветки). Инструкция игроку: «Распакуйте архив целиком и откройте `index.html`». Сообщи одно действие, которым можно проверить изменение. Для передачи результата без PR дай путь к локальной игре или готовый ZIP.

В проверке **Playable build → package** у PR также есть компактный артефакт `last-tram-<SHA>`, содержащий только файлы для игры и идентификатор сборки. Ссылка на архив коммита остаётся пригодной после истечения срока хранения артефакта. Для приватного репозитория скачивание требует доступа к нему.

**После слияния в `master`.** [Playable build](../../.github/workflows/play.yml) передаёт ту же папку игры в GitHub Pages. В **Settings → Pages → Build and deployment → Source** должен быть выбран **GitHub Actions**. При первой настройке или после устранения блокировки можно запустить этот workflow вручную для `master`.

Публикация завершена, когда задание `publish` успешно, а по адресу `page_url` открывается партия нужной версии: `revision.txt` соответствует SHA в `master`, на карте выбирается житель. Дай игроку этот адрес. Если Pages или Actions отклонили публикацию, сообщи состояние отдельно от результата слияния и приложи ZIP опубликованного в Git коммита.
