# Словарь и решения игры

Перед работой над механикой прочитай [словарь](../../GLOSSARY.md) и относящиеся к задаче [ADR](../adr/README.md). ADR — источник действующих договорённостей; наблюдения в прототипе сами по себе их не меняют.

В задачах, тестах и обсуждениях используй игровые термины в значении из словаря. Если согласованному понятию недостаёт определения, зафиксируй его через `/domain-modeling`.

При фиксации итогов обсуждения, в том числе по `/to-spec`:

1. Найди решение по теме. Запиши контекст, выбранный вариант, рассмотренную альтернативу и причину выбора. Не приписывай участникам мотивы, которых они не обсуждали.
2. Уточнение внеси в существующую запись. Для нового решения возьми следующий номер `NNNN-slug.md` и добавь ссылку в журнал. Если договорённость **изменилась**, создай новый ADR и свяжи обе записи пометкой о замене: прежние основания остаются в истории.
3. Отдельно запиши гипотезы, критерии проверки и открытые вопросы (для игры — в [материалах плейтеста](../playtests/network.md)). Если решение ещё не принято, так и скажи; не присваивай гипотезе статус решения.
4. Верни ссылку на ADR. Вызов `/to-spec` завершён: для постановки задач требуется отдельный вызов `/to-ticket`.
