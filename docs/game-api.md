# Первое утро: интерфейсы игры

`index.html` открывается локально. В браузере скрипты добавляют функции в `globalThis.LastTram`; в Node модель доступна через `require('./game/city.js')`, `require('./game/simulation.js')` и `require('./game/movement.js')`. Каждая партия независима. Карта не владеет ни часами, ни движением.

```js
const { createCity } = require('./game/city.js');
const { startGame, advance, clockMinute } = require('./game/simulation.js');
const game = startGame(createCity('Клён'));
advance(game, 240); // те же 240 одиночных тактов, что на карте
console.log(clockMinute(game), game.residents[0].currentBuildingId);
```

## География

- `createCity(seed)` → `{seed, districts, buildings, stops, edges, starterStops}`. Сид — строка; пустое значение даёт новый сид, который можно ввести снова. Массивы уже содержат **весь** город. Это справочники; не изменяйте их при открытии территории.
- Координаты `{x,y}` в единицах улицы; `x` растёт на восток, `y` — на юг. Здание: `{id, districtId, stopId, kind: 'home'|'work', name, ring, x, y, width, depth, floors, tint, entrance: {x,y}}`. `entrance` находится на фасаде. Район: `{id, ring, name}`. Остановка: `{id, districtId, name, ring, x, y, sidewalk}`; платформа `sidewalk` и ось пути `(x,y)` различны.
- `edges` — кандидаты `{id,a,b}` между соседними остановками `a,b`. Участки неориентированные, их идентификаторы лучше брать из справочника. `starterStops` — три последовательные остановки линии. Начальная зона — `ring === 0`, первое расширение — 1.

## Состояние и часы

- `startGame(city, systems = {})` создаёт `{city, lookup, openRing, tick, residents, trains, routes, trackIds, fare, cash, fareIncome, systems}`. `lookup.buildings/stops/edges` — `Map<id, объект справочника>`. Построенные рельсы — `Set` идентификаторов `trackIds`. Маршруты `{id,name,stopIds: string[]}`, поезда `{id,name,routeId,assignedRouteId,cars,position,atStopId,...}` — отдельные сущности. `assignedRouteId` — назначение диспетчера; `routeId` — фактически обслуживаемый маршрут (при пустом перегоне `null`). `atStopId` не `null` только при пассажирской стоянке. `cash` — доступные деньги, `fareIncome` — накопленная валовая выручка от билетов.
- `tick` — абсолютное целое число от 0. `advance(game, ticks=1)` изменяет этот же объект и возвращает его. За такт: `++tick` → `systems.service(game)` → `systems.demand(game)` → продвижение каждого жителя. `clockMinute(game)` — абсолютные городские минуты, включая начальное 07:30 (не по модулю суток). `BALANCE` в `movement.js` содержит скорости, длительность стоянки, утренний разброс и денежные коэффициенты.
- Жители создаются сразу, в том числе жители закрытых районов. У каждого постоянны `id`, `homeId`, `workId`; возможны одинаковые имена. `currentBuildingId` указывает на фактическое здание **только внутри**, в пути — `null`. `position` — положение на карте. `onTrainId` — фактический поезд в салоне либо `null`.

## Спрос и обслуживание: точки подключения этапов 2–3

1. **Расписание спроса.** По умолчанию `game/demand.js` каждый день отправляет жителей на работу с 07:30, часть — с дневным визитом с 12:00, домой — с 17:30. С 21:30 поездки завершаются, новых отправлений нет. Каждое отправление вызывает `depart(game, resident, destinationId)` из `simulation.js`: он заново выбирает путь от фактического здания и возвращает `false`, если житель уже в пути, цель совпадает с источником или ещё закрыта. Занятый житель сохраняет своё перемещение; после прибытия может начать актуальное для данного периода, без очереди пропущенных дел. При увеличении `game.openRing` новые жители включаются со следующего такта, не меняя идентификатор и положение. Спрос можно заменить через `startGame(city, { demand })`. Для панелей `cityTime(game)` из `demand.js` возвращает `{day, period, next, nextTick}`: день от 1; периоды содержат `id`, `name`, `minute` (начало по местным часам); `nextTick` — абсолютный такт начала следующего периода. Кнопка часов доводит партию до него обычными тактами.
2. **Сеть.** `systems.openLine(game)` открывает стартовую линию один раз; `systems.service(game)` продвигает поезда. Реализация по умолчанию в `game/service.js`. Для пустой сети при старте достаточно `openLine() {}`. Меняйте выпуск и расписания командами ниже: они учитывают уже назначенные посадки и пересадки.
3. **Перемещение.** Планировщик возвращает `{ mode:'walk'|'tram', legs:[...] }`. `depart` добавляет `originId`, `destinationId`, `startedAt`, `leg` (индекс с нуля). `mode` относится к пути целиком. `walkLeg(points)` создаёт пеший этап; `doorPath(building, stop)` строит вход → тротуар у остановки, `walkingPath(game, from, to)` — пеший путь целиком, `planWalk` — готовая альтернатива. Последний пеший этап **должен** окончиться в `destination.entrance`. Для остальных этапов диспетчер вызывает `stepTransit`; он возвращает `true` только при завершении этапа. Стартовые типы: `wait` и `ride`. Списание/доход от билета учитывает обработчик посадки в `game.cash`, не обработчик прибытия.
4. **Прибытия.** Только после последнего этапа симуляция устанавливает `currentBuildingId`, снимает `journey` и сохраняет `lastJourney: {originId, destinationId, mode, startedAt, arrivedAt, decision}`. Затем вызывает необязательный `onArrival(game, resident, lastJourney)`. Для истории записывайте этот факт; `lastJourney` — только последняя запись. Высадка не означает прибытие.

## Карта и панели

`createMap(svg, onSelect)` → `{render(game,focus), fit(), zoomBy(factor)}`. `focus` — `null` или `{type:'resident'|'building'|'stop'|'train', id}`. Узлы объектов имеют `data-type`, `data-id`; цель клика определяется самим SVG под текущей камерой. `art.project(x,y,z=0)` — единая проекция. Статика пересчитывается при замене партии, границы, путей или последовательности остановок. `LastTram.ui.game` и `.focus` — геттеры **текущих** объектов; `ui.select(type,id)` устанавливает фокус, `ui.render()` синхронизирует панели после команды (в том числе на паузе). Не сохраняйте `ui.game` между новыми партиями. Новые команды меняют модель, а не DOM.

## Пульт сети и выбор: интерфейсы этапов 4–5

Команды из `game/service.js` (в браузере — `LastTram`) возвращают `{ok:true,...}` либо `{ok:false,message}` без изменения состояния при отказе.

| Команда | Результат |
| --- | --- |
| `buildTrack(game, edgeId)` | Покупает один ещё не построенный участок между открытыми остановками. Обслуживания от этого не появляется. |
| `createRoute(game, stopIds)` | Бесплатно создаёт отдельный маршрут, возвращает `routeId`. Нужно минимум две разные открытые остановки, без повторов, и построенные рельсы между ними. |
| `setStops(game, routeId, stopIds)` | Заменяет порядок вызовов; между соседними вызовами поезд проходит кратчайшим построенным путём без дополнительных остановок. Несколько линий используют одни рельсы. |
| `buyTrain(game, routeId)` | Покупает отдельный поезд и возвращает `trainId`. |
| `assignTrain(game, trainId, routeId)` | Бесплатно переводит поезд; недостижимый по рельсам маршрут отклоняется. Выпуск распределяется равномерно по времени оборота. Старые обещанные поездки обслуживаются, пустой перегон и ожидание свободной фазы требуют времени. |
| `setFare(game, integer)` | Меняет цену для следующих решений; диапазон `0…BALANCE.maxFare`. |

`BALANCE.trackCost/trainCost` — цена пути/поезда. Расширение меняет `openRing` и списывает согласованную цену из `cash`; команды и пульт сразу видят новые доступные остановки и участки. Покупки не изменяют `fareIncome`.

`game/journey.js`: `planJourney(game,resident,fromBuilding,toBuilding)` — чистый расчёт на текущий такт. `journey.mode` задаёт способ всего пути; на текущий этап указывает `journey.legs[journey.leg].type` (`walk|wait|ride`). `journey.decision` — снимок у двери, сохраняется в `lastJourney.decision`. Поля `walkTicks`, `tramTicks` (или `null`, если связей нет), `accessTicks`, `waitTicks` (первое ожидание), `rideTicks` (в салоне), `transferTicks` (между высадками и следующими посадками), `exitTicks`, `transfers`, `fare`, `farePenalty` (цена в единицах времени), `rides: [{trainId,routeId,from,to,boardAt,alightAt}]`. Времена поездки указаны в тактах, `boardAt/alightAt` — абсолютные такты. У пешего жителя `decision.rides` относится к рассмотренной альтернативе, не к факту посадки.

В момент первой **фактической** посадки `journey.paid` принимает цену из снимка (в том числе `0`), а `cash` и `fareIncome` возрастают на неё. Хук `systems.onFare(game, resident, {tick,amount,residentId,trainId,routeId,originId,destinationId})` вызывается один раз, включая бесплатный билет; пересадки не дают ещё одного события. Для выручки периода суммируйте `amount` по `tick` в `[from,to)`; для прибытий используйте только `onArrival` по `arrivedAt`. Уже отправившийся житель доходит по своему плану даже после правки сети, новый получает актуальный прогноз с учётом перегона и занятых поездов.

## История для наблюдения и целей

У каждой партии с первого такта есть свой `game.history`. Все запросы принимают абсолютные такты `[from,to)`; чтобы включить текущий такт, передайте `to = game.tick + 1`. Записи сделаны до вызова внешних `onFare`/`onArrival`. Для открытия кольца в текущей партии история сохраняется, для новой игры начинается заново.

- `arrivals(from,to)` — новый массив отдельных неизменяемых событий у конечной двери: `{tick,startedAt,residentId,originId,districtId,destinationId,mode}`. `districtId` — район **исходного здания**. Пересадка и высадка сюда не попадают. Длительность от двери до двери — `tick - startedAt`.
- `arrivalsAt(buildingId,from,to)` — `{total,walk,tram,byDistrict}`; `byDistrict[districtId] = {walk,tram}` только для районов с прибытиями. Пустая выборка: все итоги нулевые, `byDistrict: {}`.
- `fares(from,to)` — отдельные неизменяемые события оплаты с полями хука `onFare`; `revenue(from,to)` — сумма их `amount` по **всей сети**, независимо от двери назначения и расходов кассы.

`compareMorning(city)` (`game/experiment.js`) запускает две новые партии на неизменяемой географии `city`: вторая покупает поезд на стартовый маршрут до такта 1. Возвращает `{from,to,control,changed}`: границы первого утра 07:30–09:00 и два независимых объекта истории для тех же запросов. Активную партию, в том числе после открытия кольца, опыт не изменяет. Этот опыт доступен для зданий стартовой зоны; журнал живой партии ведётся для всех открытых зданий.

На карте `createMap(...).render(game,focus,flow)` принимает необязательные параметры слоя: `{enabled,buildingId,filters:{to,from,walk,tram}}`. При отсутствии фокуса здания показаны все активные перемещения; фильтры относятся только к облачкам и списку «В пути сейчас», не к журналу прибытий. Кнопки SVG и оба справочника используют тот же `ui.select(type,id)`.
